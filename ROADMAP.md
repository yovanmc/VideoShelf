## Definition

Windows video library + player — "AudioShelf for video" on the VideoTriage stack (.NET 10 WPF + WPF-UI + LibVLCSharp play-everything + SQLite). Multi-source → section → series/standalone → episode; section tags + discovery; watched/unwatched + resume; lean player + PiP; **strictly read-only** (the opt-in rename tool is the only mutation). Self-contained — all playback/thumbnails/metadata from bundled libVLC, **no external tools (ffmpeg/HandBrake) on PATH**, no network for content.

## Decision log & gotchas

- **Feature-expansion (spec revised 2026-06-11, [PR #2](https://github.com/yovanmc/VideoShelf/pull/2)):** a research pass added 10 features + embedded track pickers and **reversed three earlier cuts** — **resume/continue-watching** (#5), **auto-play next episode within a series** (#10, settings-toggle, standalones never), and **embedded subtitle + audio-track pickers** (live from libVLC; no sidecars/downloads). Plus search (#1), seek-preview thumbnails (#2), sort (#3), recency rails (#4), unwatched badges (#6), chapter nav (#7), frame capture (#8), missing-file detection (#9). Still OUT: playback-speed, external subtitle sidecars/downloading, whole-library continuous play, online metadata scraping.
- **Execution workflow adopted ([PR #3](https://github.com/yovanmc/VideoShelf/pull/3)):** VideoTriage-style one-phase-per-run runbook; superseded as canonical state by this ROADMAP.
- **libVLC versions (pinned, restored clean):** `LibVLCSharp 3.9.7.1`, `VideoLAN.LibVLC.Windows 3.0.23.1`, `LibVLCSharp.WPF 3.9.7.1`. Do not move to 4.x. (Plan pins were older; bumped to latest 3.x that restores.)
- **Testability pattern (mirror for all libVLC/WPF work):** abstract native/UI behind an interface (`IThumbnailService`, `IPlaybackEngine`); put ALL logic in plain VMs/services unit-tested with a fake; keep the THIN concrete (`LibVlcThumbnailService`, `LibVlcPlaybackEngine`) and the Views/PiP **uncovered by unit tests** — they are integration, verified by the Phase 6 screenshot harness.
- **Visual verification DEFERRED to Phase 6:** no launch hooks/fixture exist yet, so the shell (Phase 2), player, PiP (Phase 3) and discovery (Phase 4) ship without an eyes-on pass. Phase 6 MUST do a full retroactive screenshot sweep. The Phase-2 cross-thread bug (below) shows tests alone are insufficient for UI correctness here.
- **Cross-thread `ObservableCollection` gotcha:** never `ConfigureAwait(false)` on a load chain that ends by mutating a UI-bound collection — the continuation lands on a thread-pool thread and WPF throws `NotSupportedException`. Keep heavy work inside `Task.Run` but resume on the captured UI context. A `SynchronizationContext` regression test guards this.
- **Theming rule (caused regressions in a sibling project):** never override/re-base a WPF-UI themed control's Style/ControlTemplate for cosmetics — additive (Opacity/RenderTransform) only.
- **PiP re-parenting (highest Phase-3 integration risk):** one libVLC `MediaPlayer` can host only one `VideoView`; on PiP toggle the inline surface must be cleared (`MediaPlayer = null`) before the mini-player claims it, else video blanks/freezes. Verify in the harness.
- **Seek-preview (#2) scope:** Phase 3 implements the testable seam (cached, fail-safe) and snapshots the live frame; a dedicated off-screen preview decoder is deferred to Phase 6 polish.
- **Git:** stale `.git/index.lock` → delete & retry; remove worktree before `git branch -d`; `gh pr merge` from the main repo root.
- **Minor deferred:** `LibraryViewModel` sort/search `_pending` task race (harmless); unused `db` param in `ScanService` (cosmetic — reserved for future transaction scoping).
- **History note:** Plan-1 + spec PRs (#1, #2) and the docs PRs (#3, #5) were squash-merged; feature phases use `--merge` from Phase 2 on.
- **M4 planning decisions (2026-06-11):** (1) **Home landing + Browse nav** — a new `AppView.Home` Discovery landing is the default; existing browse becomes `AppView.Browse`; `MainViewModel` gains the view switch + a `SectionDetail` host. (2) **Full weighted scoring** for For-you/Pick-a-tag — pure `DiscoveryScoring`: exponential recency decay (14-day half-life) builds per-tag affinity from watch history; section score = summed overlapping-tag affinity × (0.5 + 0.5·unwatched-ratio); For-you excludes already-watched sections. (3) **Dedicated section-detail view** hosts the tag editor (pills + autocomplete from `GetAllTags`). New Core: `resume_updated_at` column (guarded migration) to order continue-watching by recency, since `watch_events` clears resume on full-watch. Likely tiny Core add: `LibraryRepository.GetSection(long id)` for the section-detail load. Tags remain **section-level only** (spec §13).
- **M5 planning decisions (2026-06-12, plan [M5](docs/superpowers/plans/2026-06-12-videoshelf-rename.md)):** (1) **Naming = canonical + editable** — default proposal `"<Base Title> <NN>.ext"` built by a pure `CanonicalNamer` so it re-parses to the same `(title, episode)` via `TitleParser` (rescan re-groups identically); standalone series (single file) get no number; every target editable inline. (2) **Scope = per-series** — loads via `GetVideosForSeries(seriesId)`. (3) **Undo = in-app one-click** — manifest written to disk BEFORE any move; last manifest path persisted in `settings` key `last_rename_manifest` so Undo survives a restart. (4) **All logic in `VideoShelf.Core.Renaming` behind a new `IFileSystem` seam** (mirrors `IThumbnailService`/`IPlaybackEngine`): `RenamePlanner` (flags Unchanged/Ready/SourceMissing/TargetExists/DuplicateTarget/InvalidName), `RenameExecutor` (manifest-first, 2-arg `File.Move` never overwrites, re-verify at apply time, tolerant Undo), `CanonicalNamer`. (5) **DB repath = new `LibraryRepository.UpdateVideoPath(id, old, new)`** in one transaction — updates `videos.file_path` **+ `raw_filename`** (Search mirror) **+ path-keyed `grouping_overrides.file_path`**; watched/resume/tags key off ids → survive untouched. (6) **Entry point = section-detail series cards only** ("Rename files…" button → new `AppView.RenameTool` host via `SeriesViewModel.RenameRequested` bubbled through `SectionDetailViewModel`); browse-view series cards left unchanged this milestone (revisit Phase 6). (7) **Views screenshot-unverified** until the Phase 6 sweep — concrete `RealFileSystem` + `RenameToolView` are integration-only, as with prior phases. Note for executor: `InMemoryFileSystem` test helper lives in Core.Tests and App.Tests references it (csproj `<ProjectReference>`); if that doesn't build, copy the helper — STOP-and-report guidance is in the plan.
- **M5 shipped (2026-06-12, [PR #13](https://github.com/yovanmc/VideoShelf/pull/13)):** all 7 planning decisions landed as written; 200 tests (101 Core + 99 App), 0 failures. Durable facts: (a) **`Video` record positional order** is `(long Id, long SeriesId, string FilePath, int EpisodeNo, string RawFilename, string Format, double? Duration, string? ThumbnailPath, bool Watched, string AddedAt, bool Missing)` — confirmed against the real model (the plan's test helper matched). (b) **Rename safety pattern** (reuse for any future on-disk mutation): write the JSON undo manifest **before** any move (`WriteAtomic` = write `.tmp` then Move), use the **2-arg `File.Move`** (throws on existing target — never overwrites), **re-verify source-exists/target-free at apply time** (disk may have changed since planning), and make Undo **tolerant** of partially-applied batches (skip entries whose move never happened / whose old path is reoccupied). (c) **`UpdateVideoPath(id, old, new)`** updates three things in one tx: `videos.file_path` + `videos.raw_filename` (the Search mirror — easy to forget) + path-keyed `grouping_overrides.file_path`; everything else (watched/resume/tags) keys off stable `videos.id` and survives a repath untouched. (d) **Cross-project test helper**: `VideoShelf.App.Tests.csproj` **already had** a `<ProjectReference>` to `VideoShelf.Core.Tests.csproj`, so `InMemoryFileSystem` was shared directly (no copy needed). (e) **Adding a ctor param to `MainViewModel`** (the new `RenameToolViewModel`) required updating 3 existing App.Tests construction sites (`MainViewModelTestFactory` + two test files) — expected fan-out, not a regression. (f) **Rename views remain screenshot-unverified** — Phase 6 must include `RenameToolView` + the section-detail "Rename files…" entry in the retroactive sweep.
